# AI 补充校园公开栏目

使用方法与协议依据见 [AI 接口配置](ai-provider-management.md)。基础输入为接口地址与 API Key；程序自动读取模型、检查连接和启用配置，点击“一键搜索”完成发现、筛选与官网验证。默认综合，八类模板可选。自动补充保持默认关闭；主动开启时按学校至少间隔一小时，不因启动或打开配置表单隐式收费。

## 两条发现路径

- DeepSeek 官方：通过原生 `web_search` 获得结构化搜索结果。每次最多两次服务端搜索、2048 生成 token、八条候选、60 秒 API 响应及累计 2 MiB 响应。
- 自定义兼容服务（Chat Completions 或 Messages）：先读取本校公开首页和重点部门页面，最多六次请求与两层探索，汇集最多80条真实链接及20 KiB证据，再由模型返回候选 JSON。生成上限1024 token；接收器仅采纳已观察链接，给候选附上出处和 HTML 哈希。没有官网证据时模型调用为零。这是软件抓取加模型筛选，记录为 `official_site_crawl_ai_selection`。

## 原生结果与有限覆盖

仅结构化 `web_search_tool_result` 中的 `web_search_result` 作为原生检索证据；普通回答中的 URL 不算。完整 `end_turn` 接收有效结果。`max_tokens`、`pause_turn`、`tool_use`、`stop_sequence` 或 `model_context_window_exceeded` 如果已有有效真实工具结果，可采纳这些部分结果，并标注不完整；不自动续接。拒绝、未知或缺失停止原因、非法块、其他工具错误都不能冒充成功。`max_uses_exceeded` 仅在已有真实工具结果时保留结果，并显示搜索受限；只有上限错误仍失败。成功检索但没有命中可返回零候选。

两条路径均拒绝外校域、假后缀、带账号的地址、IP、登录页、附件及单条新闻；公开 HTTP 候选转 HTTPS 后读取。模型不能写入验证状态、通知正文或办事日期。八条上限之后仍检查响应中是否包含错误，不用数量上限掩盖失败。

## 实际来源准入与记录

候选由 `SchoolOnboarding` 实际读取官网，检查栏目和正文，成功后与原有来源合并。不可访问、需要账号或不形成通知列表的候选不会变成可用公开通知来源。学习资源入口发现和资源全文、购买权限、个人账号可用性是不同验收；AI 不推断权限。

记录保存至 `ai-schools/<学校ID>.search.json`，包含路径、模型、模板、实际用量、公开候选及时间；兼容筛选使用 `grounded-selection-v1`，原生搜索使用 `search-v1`。不包含 Key。记录或种子原子写入失败时停止接入；爬虫 `report.json` 的 `model_calls: 0` 仅统计校验阶段。总模型调用与用量单独记录，官网覆盖不能以某次成功替代全校验收。

## 验证边界

离线契约测试覆盖混合协议地址、自动模型选择、鉴权失败、畸形响应、真实部分工具结果、模型编造链接、外校域、页面预算与读取失败零调用，以及连接和学校加载界面恢复。真实 API 可用性和搜索质量须有真实响应和实际候选校验记录；离线测试不代替网络验收。常规学校接入及通知采集仍不使用模型。
