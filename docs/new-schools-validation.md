# 北华大学与长春理工大学公开来源核验

核验日期：2026-10-03（Asia/Shanghai）。本文件记录两校可信入口、真实页面样本和覆盖限制。学校包的 `categories` 是允许的分类集合，不代表六类信息已经全部采到；HTTP 200 也不代表页面已通过列表、正文校验。

配置入口为 [`beihua.auto.json`](../configs/schools/beihua.auto.json) 和 [`cust.auto.json`](../configs/schools/cust.auto.json)。两校各提供 8 个经官网确认的部门/栏目起点；运行时仍使用同一套 C++/Qt/Lexbor 解析和校验，学校包未填写专属 CSS。自动发现最多请求 24 页，成功启用必须通过有效列表与首条正文检验。

主站和部分部门使用 31—32 位十六进制详情 ID。通用解析支持有界的 24—64 位十六进制详情 ID，同时限定可信学校主机、HTTPS、无认证信息和无显式端口。官网通知的标题与日期分别在 `.title` 和 `.time`；研究生列表的发布日期为行内裸文本；就业列表使用 `.item-list > .item` 与 `.n-time`。这些布局的兼容逻辑位于通用 `HtmlAdapter`，未写成两校特例。

研究生页面在主列表之前还放有其他栏目的侧栏条目。旧通用规则曾将 `/xkjs/pggz/` 的侧栏详情选作培养和研工栏目的首条，实际正文请求返回 403，导致这两个公开栏目被禁用。修正后，如果当前栏目路径下存在可验证的十六进制或 `.jhtml` 静态详情，只收取同栏目路径的这类详情；既有 `/info/` 与吉林大学参数式详情规则保持原行为。培养历史页现在首条为上述 **2026-02-26 重修申请通知**；研工首条为置顶的 [智慧城市竞赛通知](https://yjs.cust.edu.cn/yytz/yg/7b84a4b16ac94fa28e9761c4ac106558.htm)，发布于 **2025-09-12**。这两个首条的独立 HTTP 样本均为 200，正文解析均通过，研工首条同时取得 PDF 附件；置顶的历史通知不能因位于列表首行而归入今年。

## 样本与验证证据

- HTTP 原始样本存于 `tests/fixtures/beihua/` 与 `tests/fixtures/cust/`。
- [`new-schools-fetch.json`](../evidence/new-schools-fetch.json) 记录请求 URL、最终 URL、时间、状态、字节数与 SHA-256，失败保留错误原因。开发期脚本仅用于生成固定样本，软件运行不依赖 Python。
- `SchoolCoverageTests.cpp` 使用真实样本验证最小可信种子、12 类列表布局/内容、10 类正文、登录页与动态壳误识别保护；每个列表断言具体官方条目、发布日期、标题及来源边界。额外反例验证侧栏详情不会抢占主栏目首条。
- 离线测试写出 [`new-schools-offline-observations.json`](../evidence/new-schools-offline-observations.json)，其中的数量来自实际 C++ 解析。必须结合测试退出状态判断，存在 JSON 文件本身不能证明通过。
- 最新 Release 完整学校契约测试 **28 项通过、0 失败、0 跳过**，包括 12 个列表、10 个正文及安全/未知日期/侧栏反例；日志为 [`stage4-school-coverage-detail.log`](../evidence/stage4-school-coverage-detail.log)。项目完整检查也已通过 14/14 个测试目标，其中包括旧 `prototype_contracts` 与 `onboarding_contracts`，保留东北电力大学与吉林大学原有行为。
- 两校 C++ 实网自动接入与整校更新验收由项目本轮实网报告记录；本文件的 HTTP 样本结果不能替代该验收。
