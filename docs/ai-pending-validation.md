# AI 待接入补充与搜索反馈验收

2026-10-06，CampusPulse 0.1.3 本地构建。

## 本次修正

原来两处排除集合都包括所有来源，导致已列入目录但仍待接入的 URL 无法重新搜索和校验。现在只有已启用且具备解析规则的来源进入排除集合；待接入目标带着名称、公开地址和原失败原因进入搜索上下文。兼容服务先实际读取目标页面，再让模型筛选证据；原生服务仍须返回真实工具搜索结果。相同入口沿用原来源 ID，不生成重复行。

“来源”页增加“用 AI 补充此来源”，只选择目标并切换页面，点击“一键搜索”才发起模型请求。AI 页下方展示真实候选与待接入目标、各自校验状态、实际接入栏目、失败原因、用量和进度。结果按学校保存在 SQLite，学校配置应用后的页面重建会读取原结果。恢复未完成搜索不会自动调用模型。

实网测试还发现并修正了校验种子父目录未创建的问题，以及原生候选过滤对 WebPlus 移动文章和 PDF 查看器过宽的问题。校验失败时从实际扫描子目录读取报告，保留具体原因。

## 验证结果

- 全套 CTest 23/23 组通过。最后的界面调整后补跑6组相关界面测试，全部通过。
- 新回归覆盖待接入与已采集来源分离、排除登录/外校入口、定向请求上下文、首页没有链接时仍读取目标、保持页面请求预算、原来源 ID 修复、失败候选立即显示、记录按学校隔离、重新构造页面恢复结果、来源按钮不隐式启动请求及文章/PDF过滤。
- 使用用户已经保存的本机提供方配置，在隔离通知数据库中运行生产 AI 页面，完成真实 DeepSeek 原生搜索。修正后的搜索返回4个公开候选，其中“学生通知”通过真实列表及正文校验，新增1个来源；原来已可采集的来源不计入新增数量。该轮模型调用1次，接口报告输入10522 token、输出1030 token。此前定位目录问题的真实调用另计，输入8773 token、输出1034 token。
- 验证扫描最多24次页面请求、每次之间间隔3秒；报告保留未扫描队列。本校全部来源、历史数据与所有待接入入口没有完成全量验收。其他候选和待接入目标仍显示未通过状态，不冒充已采集成功。
- 真实结果通过生产页面重新读取并渲染，没有额外模型请求。证据位于本机 `evidence/ai-pending-20261006/`，不纳入源码仓库；记录与截图不包含 API Key。密钥留在原 DPAPI 配置中。

## 验收入口

`campus_ai_pending_live_probe` 默认不随普通构建生成，须显式构建。参数必须指定学校配置、本机提供方目录和新的证据目录；`--replay` 只读取并渲染已有结果，不调用模型。该探针使用生产 `AiSourcesPage`，独立通知库和独立界面设置，不修改用户的订阅、待办或收藏。

本次交付保持0.1.3。生成新的本地安装包与便携包，不覆盖原来保存的预览包，也未发布新的 GitHub Release。
