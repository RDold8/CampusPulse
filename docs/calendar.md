# 日历与 ICS 导出

2026-10-03，第4步的日历和文件导出契约。日历读取“我的待办”的 `PersonalTask`，不会从通知发布日期、标题中的学年或采集时间推断截止日期。

## 使用

1. 从通知建立待办，核对办理日期或准确时刻，选择时间来源并确认。日期待定的事项可以保存，暂时保留在“我的待办”。
2. 打开“我的日历”，蓝色加粗日期表示有未完成事项，右侧显示选中日期的事项。默认只显示未完成；切换“全部（含完成与取消）”可查看历史。
3. 选中事项后点击“编辑待办”，使用与待办页相同的编辑器。修改日期会同步到日历，并跳转到新的日期；原文更新后的复核标记保留。
4. 日列表可多选，点击“导出选中任务 .ics”；“导出当前月份 .ics”导出当前月、当前显示选项下的所有已确认事项。即使界面尚未刷新，导出仍重新读取任务的当前时间与版本。
5. 如需在手机中保留提醒，勾选“包含已启用的提醒”。只为明确启用提醒的未完成任务写入 `VALARM`；完成与取消任务不写入提醒。
6. 将 `.ics` 文件传到手机，用目标日历应用导入后核对日期、中文标题和闹钟。本机编辑或标记完成不会自动更新已导入的手机日历。重复文件导入是否更新同一事件取决于日历应用，稳定 UID 本身不能保证不会重复。

“今天”使用学校配置的 IANA 时区。准确时刻按当前学校时区投影成日历日期；仅日期保留原有日期精度，不添加 23:59 或假定持续时间。已有任务的提醒钟点继续使用任务保存的时区。

## 文件与时间规则

采用 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html) 的 `VCALENDAR` / `VEVENT`。导出内容包括用户选择的个人事项、备注和关联通知原文。

| 任务字段 | 输出行为 |
|---|---|
| 未知时间、没有确认来源或确认时刻 | 不进入日历，不允许直接导出 |
| 仅日期 | `DTSTART;VALUE=DATE`；单日 `DTEND;VALUE=DATE` 为次日，结束日不包含在事件内 |
| 准确时刻 | UTC `DTSTART`，使用 `Z`；不添加 `DTEND`、时长或虚构截止钟点 |
| `calendar_uid` | 作为稳定 `UID`；标题、日期与状态修改后保留 |
| `revision` | 作为 `SEQUENCE`；导出不会修改任务版本，原样重复导出内容一致 |
| `created_at`、`updated_at` | UTC `CREATED`、`LAST-MODIFIED`、`DTSTAMP` |
| 原文 URL、时间来源和说明、备注 | 输出 `URL` 与 `DESCRIPTION`，保留用户确认来源 |
| 未开始 / 进行中 | `STATUS:CONFIRMED`，另保留任务状态字段 |
| 完成 | 标题显示“已完成”，任务状态为 `completed`；不写 `VALARM` |
| 取消 | `STATUS:CANCELLED`，保留取消任务记录；不写 `VALARM` |

提醒不改变时间精度。准确时刻按用户设置提前分钟输出相对 `TRIGGER`；仅日期按提前天数和单独设置的钟点计算 UTC 绝对触发时刻。无效时区、夏令时导致不存在或不唯一的提醒时刻会明确报错，用户可修改提醒钟点后再次导出。是否实际播放或显示导入文件的闹钟取决于手机日历。

库负责 UTF-8 文本、反斜线、逗号、分号、换行转义与 75 octet 折行，文件使用 CRLF。导出前校验必需字段、重复 UID、原文 URL 和 libical 的事件结构约束。写入成功后界面才显示成功；空选择、无可导出项目、目标不可写或提交失败均显示原因。

## 依赖与代码边界

[libical 3.0.20 官方源码](https://github.com/libical/libical/tree/v3.0.20)已用 Windows/MSVC 2022 独立构建验证，核心 C 静态库可用；构建证据位于 `evidence/libical-probe/`。依赖通过官方 tag 的源码 zip 固定，SHA-256：`7b48f3f67e241e5efa620cabfe04392eb666917a93e8dfc825f046346f7fa6e7`。采用其 MPL 2.0 许可分支，分发保留上游许可和来源信息；不启用 C++ bindings、GLib、示例、上游测试和文档构建。

本机 CMake 4 配置需为此依赖设置 `CMAKE_POLICY_VERSION_MINIMUM=3.5`；上游头文件生成使用 Perl，当前机器可用位置为 `C:/Program Files/Git/usr/bin/perl.exe`。正常运行和文件导出不需要 Perl。没有引入自有 ICS 格式替代库。

- `src/application/CalendarService.*`：纯 C++ 投影、已确认时间资格、月/日过滤和历史状态过滤。时区投影通过回调注入，不依赖 Qt 或 libical。
- `src/adapters/IcsExporter.*`：唯一使用 libical C API 的运行时边界；UTC、全天事件、稳定身份、描述、状态和可选闹钟。
- `src/adapters/ArtifactWriter.*`：文件提交与 Windows 写入错误处理，与学校包写入共用。
- `src/desktop/CalendarPage.*`：Qt 月历、日期列表、编辑、导出和结果反馈；日期转换使用 `QTimeZone`。
- `tests/CalendarTests.cpp`：时间跨 UTC 日边界、范围隔离、稳定版本、UTF-8/转义/折行、全天/准确时刻、可选闹钟及失败行为。
- `tests/CalendarDesktopTests.cpp`：真实 Qt 控件的日期/历史过滤、同一编辑器修改日期、多选/月导出、最新任务读取和失败反馈。

自动化测试使用 `QT_QPA_PLATFORM=offscreen`，不操作其他虚拟桌面的前台窗口。文件格式和软件界面测试分别记录；没有目标手机设备时，不把格式检查写成“手机导入已通过”。Windows 本地提醒的调度和投递记录由独立的提醒服务负责，与是否导出文件分开。

## 本地提醒与投递记录

任务编辑器明确启用提醒后，应用运行期间每15秒扫描同一本地数据库中所有学校的个人待办。准确时刻减提前分钟；仅日期按用户设置提前天数及钟点在任务时区转换。未确认、未知时间、完成、取消和禁用的任务不投递。软件退出期间已过期触发不补发；运行期间允许5分钟内短延迟，超过此范围记为expired。

数据库版本5增加 `reminder_delivery`，唯一键为任务ID和UTC触发时刻；修改标题/备注不会重新发送同一提醒，改期可产生新的触发记录。提交前先持久化attempting，再记录submitted、failed或expired。上次提交中断在启动时标记interrupted，不盲目重试，避免重复催办。

应用内状态栏显示提醒；Windows系统托盘消息在平台支持且未显式禁用时调用。submitted只代表提醒通道调用完成，不代表系统一定显示横幅或用户已阅读。多个同时触发的事项可能依次覆盖状态栏，历史投递记录保留在数据库。系统关闭应用时不提供常驻后台服务。

本轮正式Windows页面、ICS和应用内提醒在桌面2实测，证据为 `evidence/stage4-native-verified.json` 与 `stage4-native-window-proof.json`。没有向桌面1发送系统横幅；目标手机导入仍未实测。
