# CampusPulse 桌面原型 0.1

2026-10-04：C++20 + Qt Widgets + SQLite + Lexbor HTML/CSS选择器 + libical ICS。东北电力大学是第一份学校配置，来源参数独立于核心和界面。源码已公开，Windows 0.1.0预览安装版与便携版见[下载与安装](windows-release.md)；仍是早期原型。

## 使用

打开 `dist/CampusPulse/CampusPulse.exe`。首次启动本地为空时会读取官网；以后打开读取本地缓存，点击“更新官网”重新读取已接入且本机未暂停的栏目（学工前两页，其余首页）。

界面分为“通知”“来源”“我的订阅”“我的待办”“大学”“AI补充”“日历”“学校资源”。“来源”展示完整配置目录，包含六个可采集栏目和待接入的就业网。选择来源可以“更新此来源”或“暂停更新 / 恢复更新”；本机偏好立即保存，不改社区配置，全部暂停仍可查看缓存。显示最近尝试、最近完整成功、最新发布日期、成功页数、本轮列表条数和错误。第二页失败时显示部分成功，已经保存的数据与历史正文保留；进程中断后重启显示上次更新中断，允许重试。

“学校资源”收集学习资料和实用入口，默认显示全部类别、全部学习阶段。支持后台发现、访问检查、用途与官网出处详情、收藏以及组合筛选。首次进入且缓存为空时发现一次，以后先读缓存；通知更新与资源发现各自保留进度。东北电力大学作为首个实网示例，通用模块可由社区包增加其他学校。资源状态不代替使用资格判定，外部官网推荐链接保留待核实标记。详见[学校资源](school-resources.md)。

需要学校账号的来源显示“需要登录”，与一般“待接入”分开。点击“查看需登录来源”可定位并看到说明，通过“打开官方登录入口”在系统浏览器访问学校页面。当前版本不连接浏览器登录会话，登录后也不会自动启用采集。详情见 [来源登录入口](source-access.md)。

“大学”提供官网输入入口：填写 `www.neepu.edu.cn` 、`www.jlu.edu.cn`、`www.beihua.edu.cn` 或 `www.cust.edu.cn`，点击“加载大学配置”。输入先匹配已安装社区学校包里的官方首页主机名。东北电力大学使用既有配置；吉林大学首次由后台自动发现公开栏目，保存样本，验证列表和首条正文，再生成学校配置、切换学校和首次更新通知。界面显示扫描进度；以后使用已生成配置，点击“更新官网”增量读取列表。通知、订阅和待办按学校隔离。当前目录收录这四所学校；未收录高校先由社区补充经核验的最小学校种子。自动识别流程见[官网后台自动接入](automatic-onboarding.md)。

官网入口不接受普通网站、伪装的域名后缀、IP、本地地址、账号密码、显式端口、查询参数、片段或栏目路径。只接受完整官网主机名的精确匹配；不会仅凭 `.edu.cn` 后缀放行，也不会在校验前请求输入地址。后续采集只访问学校包允许的主机，重定向继续检查。目录本身属于受信任的项目配置，须由维护者核验，界面输入不能新增信任域名。

启动默认显示本机当前年份；年份按官方发布日期划分，年份选项从新到旧排列，并保留“全部年份”“日期待核实”。不会按标题里的学年推测发布日期。来源、年份、主题、关键词可以组合筛选；“清除筛选”恢复今年、全部来源与主题。

搜索框检索标题和来源，多个词用空格分隔且全部匹配；在主题下拉框选择“重修 / 缴费”筛选重修相关通知，继续搜索“缴费”可缩小范围。新增“缴费”主题独立检索标题及已缓存正文中的缴费/交费词。该重修主题保留原快捷入口的范围，不会将其他缴费信息归入重修。主题分类是标题关键词提示，不是人工审核的适用资格判定。

列表“主题提示”分别识别标题中的“重修”“补考”“缴费”，按这个顺序用` / `连接。例如重修课表显示“重修”，补考安排显示“补考”，补考缴费通知显示“补考 / 缴费”，三个词都有显示“重修 / 补考 / 缴费”。旧缓存立即生效，通知页和订阅页一致；其他通知继续显示原有主题，筛选分组和已保存订阅保持原有规则。

在“通知”页选好年份、来源、主题和关键词后，点击“保存为订阅”，填写名称并保存；也可在“我的订阅”直接新建。编辑器支持多选来源、主题与阶段，设置全部包含、任一包含、排除关键词，并预览当前缓存的命中数。“今年”随年份变化，“固定年份”保持指定年份。订阅按学校保存在本机，可编辑、暂停、恢复或删除；删除只移除规则，保留通知和正文。选中命中通知可跳回通知页查看详情。

点击“更新官网”采集后，订阅页面重新匹配缓存。阶段栏是申请、报名、缴费、安排、结果、公示或待核实等标题提示；结果与公示不会同时推断成申请、报名或缴费。关键词检索标题与主来源名称，来源选择则匹配该通知出现过的全部栏目。规则和数据字段详见[本地订阅规则与数据](subscriptions.md)。

选择尚无缓存的通知后按需读取正文，已有正文直接读本地，结果保存在本地；官方原文和附件用浏览器打开。附件保持链接，没有下载学生名单。正文失败时可直接打开原文；来源失败会显示错误，不抹掉既有缓存。

选中通知后点击“加入我的待办”，填写办理事项与操作类型。日期默认待定，可以直接保存；设置“仅日期”或“准确时刻”时需选择个人计划或核对原文后的时间，并勾选确认。摘自原文的时间必须填写时间说明。仅日期不补出截止钟点，准确时刻按学校时区输入，存为UTC。一条通知可添加多个待办；报名、缴费、申请等操作独立保存和完成。保存后进入“我的待办”，可以搜索、筛选、编辑、开始办理、标记完成、撤销完成、取消或恢复。

“查看关联通知”返回详情，“刷新原文”重新读取已有正文。标题、发布日期、正文或附件等内容修订变化后，待办显示“待复核”，已确认时间与完成状态保留。核对后点击“确认已核对当前原文”；需要调整时间时另外编辑并确认。阅读通知和订阅命中不会自动创建或完成任务。“日历”显示已确认日期的待办，支持选中任务/月份的ICS导出。启用提醒后，应用运行时检查触发并记录投递；退出期间已过期的触发不补发。手机传入ICS后手动导入系统日历。详见[日历与ICS](calendar.md)。详细规则见[个人待办与确认时间](tasks.md)。

数据库默认保存到Qt的AppLocalDataLocation（Windows通常位于当前用户LocalAppData的CampusPulse应用目录），可用 `--database <文件>`明确指定。安装/源码目录不保存默认用户数据库。启动自动事务迁移至版本7，保留旧通知、正文、修订、来源、订阅、个人待办与提醒投递记录，新增独立学校资源表；旧版没有采集时间，因此显示“未记录”，最新发布日期从真实缓存读取。一个数据库同时只由一个CampusPulse窗口使用，避免把另一个窗口仍在进行的更新误判为中断。

## 当前范围

已实现：东北电力大学六份配置化列表、吉林大学后台自动发现与生成配置、学工前两页有界采集、年份分层、来源筛选、关键词筛选、分类及阶段提示、正文与附件链接、本地缓存、列表/正文变化历史、重复导入幂等、源码分层、完整来源目录、单来源更新、持久暂停、更新进度与部分失败状态、中断恢复、受保护的官网输入及学校包加载、保存订阅、共用匹配规则、多来源关系、个人待办、确认日期、办理状态、原文复核与学校隔离。

目前读取校本部15条、教务两个栏目各20条、学工前两页各10条、团委通知及团学动态各自首页；有界翻页并不代表全量历史采集。就业网动态来源尚未接入，没有全部来源覆盖、自动截止识别或移动同步。网页发布日期不会被当作办理截止。已过期通知保持历史信息，用户需核对原文；可以手动建立缴费待办并确认时间、启用本地提醒。

## 编译与验证

工具链：Visual Studio 2022/MSVC 19.44、Qt 6.8.3 msvc2022_64、CMake、Lexbor 2.5.0。Qt SDK安装在 `D:\CampusPulseSDK`，项目通过参数引用，不改系统PATH。安装器在中文SDK路径的qmake输出解码失败后，已确认解压结果，迁移到ASCII目录并完成配置修正。

```powershell
.\tools\build-desktop.ps1 -QtRoot 'D:\CampusPulseSDK\6.8.3\msvc2022_64'
.\tools\package-desktop.ps1 -QtRoot 'D:\CampusPulseSDK\6.8.3\msvc2022_64'
```

构建脚本运行CMake、部署Qt运行库及CTest；首次配置下载带SHA-256校验的固定Lexbor与libical版本。桌面运行不需要Python或SDK。源码仅通过传入QtRoot定位本机SDK，不要求其他贡献者复制同一磁盘路径。

离线样本回归：教务两个列表各20条，校本部/学工/团委不同布局、多种日期格式、完整标题、嵌入日期去除、下一页域名约束，年份/来源/主题组合筛选、UTF-8标题与发布日期、缴费正文/附件、结构失效、无效选择器、非法域名、重复导入、语义更新、正文幂等、事务回滚和数据库重启恢复。

实网验证入口：

```powershell
.\build\Release\CampusPulse.exe --verify-live --evidence .\evidence\live-proof.json --database .\evidence\live.sqlite
```

该模式读取六个官网栏目及配置的分页，选中缴费通知读取正文与附件链接，保存JSON证据和窗口截图后退出。仅在开发验证时使用，不是后台监控机制。软件正常模式需用户自己使用“更新官网”；无定时常驻任务。

## 源码阅读顺序

1. `src/domain/Notice.h`：纯C++数据与仓库接口。
2. `src/application/NoticeService.cpp`：入库与关键词分类提示。
3. `src/adapters/SchoolPackage.cpp`、`HtmlAdapter.cpp`：学校参数加载和HTML/CSS适配。
4. `src/storage/SqliteRepository.cpp`：参数化SQL、事务和历史版本。
5. `src/adapters/RefreshCoordinator.cpp`：异步网络、队列、限流与错误。
6. `src/domain/Source.h`、`src/application/SourceService.cpp`：学校来源目录、本机偏好和状态规则。
7. `src/storage/Database.cpp`、`SqliteMigrations.cpp`、`SqliteSourceRepository.cpp`：共享连接、事务迁移与来源记录。
8. `src/adapters/UniversityRegistry.cpp`：学校包目录与官方首页输入边界。
9. `src/domain/NoticeQuery.h`、`Theme.h`、`Subscription.h`：稳定键、年份策略与纯C++订阅模型。
10. `src/application/NoticeMatcher.cpp`、`NoticeClassifier.cpp`、`SubscriptionService.cpp`：两处界面共用的匹配、标题提示、订阅用例。
11. `src/storage/SqliteSubscriptionRepository.cpp`：参数化SQL、学校范围与订阅持久化。
12. `src/desktop/NoticePage.cpp`、`SourcePage.cpp`、`SubscriptionPage.cpp`、`SubscriptionEditorDialog.cpp`、`UniversityPage.cpp`：页面和编辑器；`MainWindow.cpp`组合页面，`main.cpp`管理当前学校会话。
13. `src/domain/PersonalTask.h`、`src/application/TaskService.cpp`：待办、时间精度、确认、逾期和原文复核规则。
14. `src/storage/SqliteTaskRepository.cpp`、`src/desktop/TaskPage.cpp`、`TaskEditorDialog.cpp`：任务事务、预期版本检查与界面操作。

Qt边界在适配器、存储和桌面模块；domain/application不包含Qt窗口或SQL。该原型覆盖了路线中的部分阶段，不代表完整全国高校平台已建成。


开发者可以用 `--verify-detail <唯一标题关键词> --config <学校包> --database <独立验证库> --evidence <JSON>` 实际验证特定通知正文与缴费主题匹配。此入口不创建待办，不使用AI；匹配多个通知或网络失败时明确失败。隔离测试需在执行工具进程中设置 `QT_QPA_PLATFORM=offscreen`、SDK平台插件目录和字体目录；程序包正常启动使用windows平台插件。
