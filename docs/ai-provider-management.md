# AI 提供方配置

CampusPulse 借鉴 [CC Switch](https://github.com/farion1231/cc-switch) 的提供方列表、预设、编辑表单、启用切换、密钥显隐和模型选择交互，使用原创 Qt 界面和独立配置存储。不读取 CC Switch / Claude / Codex 的本机配置或密钥，不导入其供应商广告，也不操作其他客户端。

AI 页可以添加、编辑、删除并启用提供方。按 CC Switch 配置流程提供名称、备注、官网链接、API Key、请求地址、完整 URL 开关、API 格式、认证方式、模型列表 / 手动模型、连接测试和隐藏 Key 的配置预览。请求地址始终可编辑，不锁定 DeepSeek 官方，不把自定义路由改回官方。

支持 Anthropic Messages 与 OpenAI Chat Completions 两种格式。未勾选“完整 URL”时按基址拼接：Anthropic 地址以 `/v1` 结尾时追加 `/messages`，否则追加 `/v1/messages`；OpenAI 兼容基址追加 `/chat/completions`。勾选后直接使用完整请求地址，不补路径。表单显示最终请求 URL；第三方路由路径有特殊规则时可以用完整 URL 明确指定。

认证可选按协议自动选择、`Authorization: Bearer` 或 `x-api-key`。模型可从接口获取，也可直接填写服务实际接受的模型 ID，不要求名称是 DeepSeek。普通保存不请求模型，显式连接测试按所填地址与协议发送一次短请求。只支持公共域名 HTTPS / 默认443端口，拒绝私网 DNS、IP、URL认证信息、查询和跳转；以固定公网地址建立连接，同时校验原 API 主机证书。

“获取模型”读取模型接口；DeepSeek 预设使用官方 `/models`。服务不提供列表时可以手动填写模型。“测试连接”发送最多128输出 token 的短模型请求，会消耗提供方 API token；它只证明该 API 与模型可响应，没有执行校园栏目检索。“补充栏目”才会进入候选与官网校验流程。失败显示 HTTP 状态、耗时和原因，不自动重试。

Anthropic 搜索工具模式要求路由实际返回结构化搜索工具结果；路由能响应普通模型请求也可能不支持搜索，失败会显示原因。OpenAI 兼容模式只产生模型建议，不能把普通回答、连接成功或模型列表成功当作联网搜索。自动补充默认关闭，启用后每校至少间隔一小时。调用完成显示返回用量，爬虫和官网身份识别模型调用为零。

提供方元数据保存在用户应用目录 `ai-providers/providers.json`，包含稳定ID、名称、备注、官网链接、请求地址、URL模式、模型、协议、认证方式及当前启用ID，不含 Key。默认 Key 仅本进程保留并按配置目录和提供方隔离，切换学校不丢失。选择“记住”后，Windows DPAPI 密文另存当前用户目录，绑定提供方ID、地址、协议、认证与URL模式；这些请求配置变化会撤销旧 Key 授权。其他平台暂不支持记住密钥。删除当前提供方会清空启用项，需要用户主动启用其他配置。官方环境变量 Key 不自动传给第三方路由。

配置加载和写入错误会显示在界面；Key 不进入学校包、数据库、导出、Git 或日志。服务器回显密钥的展示字段会隐藏，包含密钥的候选地址不会保存。实际接口可用性、模型名称及搜索能力以提供方响应为准；离线测试及加密回读不替代真实 API 连接验收。

代码入口：`AiProviderConfig` 负责配置校验和安全存储，`AiProviderProbe` 负责显式连接 / 模型列表操作，`AiProviderDialog` 与 `AiSourcesPage` 负责界面，`DeepSeekSearch` 区分原生工具结果和兼容候选 JSON，`SchoolOnboarding` 负责真实来源校验。
