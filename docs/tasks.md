# 闹钟待办卡片与确认时间

当前0.1.3桌面操作契约，更新于2026-10-06。功能适用于已接入的学校，学校身份、来源及显示时区由包提供；东北电力大学用于参考验证。

## 操作

1. 在“通知”选中通知，查看正文或打开官方原文，点击“加入我的待办”。
2. 填写办理事项，选择一个日期和时刻，点击“保存待办”。新事项默认是约一小时后的个人计划，默认“到时间提醒”；保存即确认你选择的个人计划时间。这个默认时间不是从通知中识别的学校截止时间。
3. “提醒我”可以选择到时间、提前10分钟、30分钟、1小时、1天或不提醒；下方直接显示实际提醒日期和时刻。取消“安排时间”可以暂不定日期。“更多设置”保留操作类型、备注、仅日期、来源及自定义提醒。选“核对原文后的时间”仍需填写原文时间说明并明确核对；程序不会验证原文是否真的规定该时间。
4. 保存后默认显示待办卡片，展示事项、办理时间、实际提醒时刻及完成状态。点击“修改时间”或双击卡片编辑；点击“完成”关闭后续提醒，支持撤销完成。卡片“更多”保留开始、取消、恢复和关联通知。页顶可切换回列表，搜索和筛选共用同一批数据。
5. 同一通知可反复加入不同事项，例如报名和缴费。它们分别保存和完成，不自动合并。
6. 点击“查看关联通知”回到通知详情，“刷新原文”重新读取正文。关联通知的内容修订变化时，待办显示“待复核”。核对当前通知和个人计划后，点击“确认已核对当前原文”；时间有变化则另外编辑并确认。

订阅命中、阅读原文和采集更新不会创建或完成待办。当前待办从通知建立，个人待办只在本机保存；内置日历、ICS导出和本地提醒已实现，手机同步尚未实现。

到点出现独立置顶提醒窗口，同时保留多条事项，直到用户点击“知道了”或关闭提醒窗口；关闭提醒不代表完成待办。“查看待办”打开事项，页顶“测试提醒”可以检查弹窗，不创建测试任务。Windows托盘可用时，关闭主窗口会留在托盘继续运行；托盘菜单可打开软件、查看待办、测试提醒或彻底退出。彻底退出、关机和睡眠期间不会检查；再次运行只补发最近5分钟内尚未投递的有效提醒，较早记录标为过期。系统横幅调用不等于系统已经显示或用户已经阅读，应用内窗口是独立的提醒通道。

## 时间与状态

| 时间精度 | 保存方式 | 规则 |
|---|---|---|
| 日期待定 `unknown` | 日期、UTC时刻、确认来源及确认时刻为空 | 可以保存；关闭提醒偏好，不产生有时间的日历项目 |
| 仅日期 `date` | `YYYY-MM-DD`，保留学校时区 | 保持日期精度；不会补出23:59或其他截止时刻 |
| 准确时刻 `datetime` | `YYYY-MM-DDTHH:MM:SSZ` UTC，保留学校时区 | 界面按学校时区输入与显示；遇到不存在或不唯一的本地时刻拒绝保存 |

发布日期不会填成办理日期。个人计划以点击保存作为时间确认；原文时间新建或修改时必须明确勾选确认。修改备注、标题或状态不要求重新确认未改变的时间。重新打开并原样保存不增加修订。时区使用学校包的`school.timezone`，当前参考学校为`Asia/Shanghai`；包以后更改时区时，已有待办保留原有时区。

保存状态为`not_started`、`in_progress`、`completed`、`cancelled`。逾期只是显示计算：未完成的仅日期事项从学校时区的次日起显示逾期，准确时刻事项在该UTC时刻经过后显示逾期。完成和取消后不显示逾期，状态可以撤销或恢复。标记完成只记录用户的操作，不核验学校是否已收款或已收到申请。

原文更新后保留待办的标题、状态、时间、确认时刻和提醒偏好，仅显示复核提示。确认核对时只更新关联修订和待办版本；不会把原文中的日期自动写入个人计划。同一正文重复刷新不会产生新内容修订，新增来源关系也不会单独触发原文复核。

## 持久化与版本

SQLite版本4增加`personal_task`，不修改旧通知、修订、来源状态或订阅记录。升级使用事务，遇到冲突回滚；拒绝打开高于当前支持版本的库。

| 字段 | 用途 |
|---|---|
| `id`, `school_id`, `notice_id` | UUID、学校范围、关联通知；一条通知可有多个UUID |
| `notice_revision_id` | 用户建立或最近核对时参考的内容修订；允许历史通知尚无修订时为空 |
| `title`, `notes`, `action`, `status` | 个人事项、备注、稳定操作键与状态 |
| `time_precision`, `time_date`, `time_utc`, `time_zone` | 单一时间事实源及精度 |
| `time_evidence`, `time_source`, `time_confirmed_at` | 时间说明、`none/personal/original_text`、用户确认时刻 |
| `reminder_enabled`, `reminder_minutes`, `reminder_days`, `reminder_time` | 第4步日历/本地提醒使用的偏好；仅日期的提醒钟点与办理日期分开 |
| `calendar_uid` | 创建时由任务UUID派生，后续修改保持稳定 |
| `created_at`, `updated_at`, `revision` | UTC审计时间；新建版本1，有效修改递增，原样保存不变 |

外键同时约束学校/通知和通知/内容修订，避免跨校引用或引用其他通知的修订。修改时携带预期版本，事务内检查并条件更新，遇到过期编辑拒绝覆盖。完成、撤销、取消、恢复和原文复核也使用同一保存机制。取消保留任务记录，本阶段未加入永久删除操作。

学校包和爬虫不会直接修改个人状态。`domain/application`使用纯C++数据与用例，Qt日期输入、网络、UUID和SQL位于桌面、适配器及存储层。

## 源码入口

- `src/domain/PersonalTask.h`：时间、状态、提醒偏好、任务视图和仓库接口。
- `src/application/TaskService.cpp`：学校范围、时间确认、状态、逾期、版本与原文复核。
- `src/storage/SqliteMigrations.cpp`、`SqliteTaskRepository.cpp`：版本4迁移、外键、参数化SQL与事务。
- `src/desktop/TaskEditorDialog.cpp`、`TaskPage.cpp`：输入、筛选、状态操作和复核提示。
- `src/desktop/NoticePage.cpp`、`src/adapters/RefreshCoordinator.cpp`：从通知创建任务、缓存正文刷新及失败反馈。
- `tests/TaskTests.cpp`、`TaskDesktopTests.cpp`：领域/存储及真实Qt控件的操作检查。
