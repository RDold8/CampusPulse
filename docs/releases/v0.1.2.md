# CampusPulse 0.1.2 · Windows 桌面预览版

修复输入北京邮电大学官网后无法接入的问题，并完善通用栏目发现和学校资源识别。

## 本次更新

- **公开网页验证**：识别 HTTP 403/412/503 的部分 JavaScript 验证页，Windows 使用独立 WebView2 临时会话取得真实公开网页后继续采集。普通页面仍直接 HTTP 读取，不消耗模型 API token。
- **陌生高校发现**：新大学草案默认扫描预算由24提高至48。优先教务等学习入口及通知栏目，补充 title / aria-label / 图片 alt 导航，排除把历史分页当作新栏目。
- **主题栏目与近期分页**：跟进双创教育、创新创业、教学服务与办事指南；竞赛、重修、补考、缴费等栏目尝试列表校验。验证到常见 CMS 或标准同来源域的下一页链接后，更新最多读取3页，未验证的分页不会启用。
- **验证和失败说明**：保留至少三条列表加首条正文的启用门槛；记录预算耗尽和未扫描入口，正确保留已验证的同校正文跳转主机。失败保留当前学校。
- **日期解析**：识别同一文章卡片上明确分开的年月与日期，保留不明确的发布日期，不从标题学年或正文活动时间推算。
- **部门资源**：“教务处概况”等介绍页面按学校资源验证；通知来源说明明确它不是通知列表。它可以出现在学生服务资源中，无需伪装成通告。
- **独立验收设置**：新增 `--settings-dir`，可配合独立数据库和自动配置目录进行界面验收，不改动默认用户设置。

## 下载

Windows 10 1809+ / Windows 11 x64，运行不需要 Python 或 Qt SDK。

- `CampusPulse-0.1.2-windows-x64-setup.exe`：当前用户安装程序。
- `CampusPulse-0.1.2-windows-x64-portable.zip`：完整解压后运行。
- `SHA256SUMS.txt` 与 `release-manifest.json`：附件校验与验收范围。
- Qt Base、Lexbor、libical 对应源码附件；SDK许可与归属随软件提供。

公开网页验证需要已安装的 Microsoft Edge WebView2 Evergreen Runtime。安装包不自动安装它；缺失或版本过旧会提示安装/更新，可访问[微软官方入口](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)。不读取个人浏览器配置或学校账号，不提交登录表单，不忽略证书错误。

## 实测与边界

Release 构建、21套 CTest、5份学校配置检查通过。最终完整部署包在桌面2从未预装的北邮官网输入开始识别学校、验证列表和正文并读取通知：48次发现请求、15个验证入口，7个来源启用已验证分页；刷新后302条去重信息，其中50条明确为2026年、153条日期待核实。竞赛分类28条，其中10条明确为2026年。学校资源发现45项，其中5项已检查可访问，包含“教务处概况”。全程模型调用0次，未增加北邮专用学校包。[北邮验收记录](https://github.com/RDold8/CampusPulse/blob/main/docs/bupt-onboarding-validation.md)区分发现、验证和去重结果；完整最终结果见发布清单。

发现预算已耗尽，报告保留未访问入口；不代表全校采集完成。北邮当期重修、补考与重修缴费通知尚未验证到，公开重修说明指向每学期信息门户通知，登录后的内容仍不采集。

源码、软件包不含真实 API Key、个人数据库或采集日志。此次没有收费 AI 调用；AI 搜索补充链、手机 ICS 导入、系统通知送达、覆盖旧安装的原地升级仍未在此版本实测。既有0.1.0安装保留。各校覆盖是部分公开入口，人工验证码、学校账号和动态 API 列表仍可能需要适配。

初版，有许多不足之处，请见谅。

# CampusPulse 0.1.2 · Windows desktop preview

This release repairs onboarding blocked by BUPT's public browser verification and improves generic discovery and school resources.

- Recognized public JavaScript verification pages can use an isolated Windows WebView2 session; ordinary collection continues over direct HTTP without model calls.
- Unconfigured university drafts now allow up to 48 page requests. Teaching entries and notice sections receive priority; icon labels are supported and history pagination is excluded from section discovery.
- Innovation and entrepreneurship, competition, retake, payment and student-service navigation is followed. A verified same-source next-page link can enable refresh of up to three pages; unknown pagination is left disabled.
- Source enablement still requires at least three list records and a verified first article. Reports retain budget exhaustion and pending navigation, and source allowlists preserve only verified university redirects.
- Explicit split publication dates are parsed without borrowing academic years or event dates from titles and summaries.
- Department overviews are handled as school resources, with a clear explanation when they are not notice lists.
- `--settings-dir` supports independent INI settings for acceptance testing.

The x64 installer and portable package require no Python or Qt SDK. Public browser verification uses a separately installed Microsoft Edge WebView2 Evergreen Runtime; it is not installed by this package. Licenses, dependency sources, checksums and a validation manifest accompany the release.

The Release build, 21 CTest suites and five configuration checks passed. The final deployed application was tested on Desktop2 from BUPT's unconfigured homepage input through identity, list/article verification and notice collection: 48 discovery requests, 15 verified list entries, seven sources with verified pagination and 302 deduplicated records after refresh; 50 have explicit 2026 publication dates and 153 have unknown dates. Competition classification contains 28 records, ten explicitly dated 2026. Resource discovery saved 45 entries, with five checked as accessible, including the Academic Affairs Office overview. No model calls or school-specific package were used. The request budget was exhausted and pending entries were recorded; this is not full university coverage. Current retake, makeup-exam and retake-payment notices were not verified; the public retake guide directs students to term-specific portal notices, and authenticated content is not collected. The final manifest records exact coverage and UI results. Keys, user databases and logs are excluded. AI supplementation, phone ICS import, notification delivery and an in-place installer upgrade retain their separate unverified status. Manual CAPTCHAs, accounts and dynamic APIs may still require adapters.

This is an initial version with many shortcomings. Thank you for your understanding.
