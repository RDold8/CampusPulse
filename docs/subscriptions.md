# CampusPulse 本地订阅规则与数据

第2步已实现的本地契约，2026-10-02。适用于所有已安装学校包；东北电力大学用于验证。`configs/subscriptions`中的复杂示例仍是未来双端配置草案，当前界面不导入该草案。

## 使用与匹配

从“通知”页保存当前筛选，或在“我的订阅”新建。保存前预览本地缓存，保存后显示命中通知；更新官网后重新匹配。规则按学校隔离，编辑保持UUID和创建时间；暂停保留规则并暂时隐藏命中，恢复后重新计算；删除保留已采集通知、正文和历史。

所有维度之间同时满足：学校、年份、来源、主题、阶段、关键词。来源、主题、阶段各自的集合内部任一匹配，空集合表示不限制。

| 字段 | 当前规则 |
|---|---|
| `schoolId` | 当前学校的稳定键，界面无需输入 |
| `sourceIds` | 任一来源键匹配通知的全部来源关系，包含旧主来源 |
| `themeKeys` | 任一主题匹配标题标签或原有主分类 |
| `stageKeys` | 任一阶段匹配标题提示 |
| `keywordAll` | 每个关键词都出现 |
| `keywordAny` | 至少一个关键词出现；空集合不限制 |
| `keywordExclude` | 出现任一关键词即排除，优先于包含规则 |
| `yearPolicy` | `current_year`、`all_years`、`fixed_year`、`unknown_date` |
| `fixedYear` | 仅固定年份有值，其余策略存0 |

关键词以空格分隔，检索标题与主来源名称；中文按字面子串匹配，英文字母采用ASCII大小写不敏感。首版不检索正文、附件或其他来源名称。“今年”按每次求值传入的当前年匹配，不保存硬编码年份；固定年份不随时间变化。年份只使用有效的官方发布日期，不读取标题中的学年；日期为空或无效时归入“日期待核实”。

主题键为 `academic_affairs`、`exam`、`retake_payment`、`competition`、`scholarship`、`campus_activity`、`career`。`retake_payment`显示“重修 / 缴费”，保持标题含“重修”的范围；再加关键词“缴费”或阶段“缴费”可缩小范围。单独的宿舍缴费不纳入这个主题。

列表的“主题提示”按标题中的原词显示：含“重修”显示重修，含“补考”显示补考，含“缴费”显示缴费；同时含有多个词时，按重修、补考、缴费的固定顺序，用` / `连接，每个词只显示一次。例如重修课表显示“重修”，补考缴费通知显示“补考 / 缴费”，三词都有显示“重修 / 补考 / 缴费”。其他通知继续显示原有主题。通知页与订阅页共用这个显示规则，旧缓存立即生效，列宽随内容调整。

列表显示文字与筛选分组各有用途：上述显示规则不更改稳定主题键、已保存的订阅或缓存主分类；“考试”仍可筛选重修、补考通知，“重修 / 缴费”分组继续按标题含“重修”匹配。标题是否包含“缴费”按该词本身判断，不用交费或付款等词代替。

阶段键为 `application`、`registration`、`payment`、`arrangement`、`result`、`publicity`、`unknown`。规则仅分析标题，可以有多个主题和阶段。当标题明确含结果、公示类词时，保留结果和公示，抑制申请、报名、缴费和安排，避免把“奖学金申请结果公示”当作新的申请入口。标题规则可能误判，阶段显示为提示，办理操作和期限以原文为准。

例如：“今年重修缴费”可设置今年、主题“重修 / 缴费”、全部包含“缴费”、阶段“缴费”；“奖学金申请”可选择奖助学金、申请阶段，并排除“公示 结果”。补考可选择考试主题、任一包含“补考”，再按需要选择报名或安排阶段。订阅只形成关注列表；第3步已实现从通知手动建立[个人待办与确认时间](tasks.md)，日历及ICS在第4步实现。

## 持久化与来源关系

SQLite版本3在原有表上增加：

| 表或字段 | 保存内容与约束 |
|---|---|
| `subscription` | UUID、学校、名称、暂停状态、各条件JSON数组、年份策略、创建和更新时间 |
| `source_occurrence` | 学校、通知ID、来源键、来源名；学校/通知/来源组合唯一，外键对应同校通知 |
| `notices.tags` | 稳定主题键JSON数组 |
| `notices.stages` | 稳定阶段键JSON数组 |

迁移在一个事务内回填旧主来源和标题提示，保留原通知字段、正文及修订记录。只有成功提交才将版本改为3；失败回滚DDL和数据。使用新库、冻结v2夹具及本机95条通知的旧库副本分别验证，避免只有空库能升级。

采集仍使用学校和规范URL生成通知身份。同一通知从另一栏目重复采集时补充关系，不生成重复通知，也不因新增来源而生成内容修订。列表保留首个来源作为主来源；来源筛选使用全部出现关系。旧版本只记录过一个来源，迁移只能恢复该记录；其他历史关系需要重新采集后补充。

名称不能为空，界面最多80个字符，服务层限制240字节UTF-8。每组条件最多64项，每项最多600字节；保存前去掉两端空白、空值和重复项，校验稳定键与固定年份。学校包移除的来源引用仍保留，编辑器显示“目录已移除”，用户可以主动取消，不静默丢掉旧规则。订阅保存采用参数化SQL，失败显示错误并保留已保存规则。

## 代码边界

- `domain/NoticeQuery.h`、`Theme.h`、`Subscription.h`：纯C++数据和仓库接口。
- `application/NoticeMatcher.cpp`：学校、年份、来源、主题、阶段和关键词匹配，通知筛选与订阅共用。
- `application/NoticeClassifier.cpp`：标题多标签和阶段提示。
- `application/SubscriptionService.cpp`：验证、保存、暂停、删除、预览与匹配用例。
- `storage/SqliteSubscriptionRepository.cpp`、`SqliteMigrations.cpp`：持久化及事务升级。
- `desktop/SubscriptionEditorDialog.cpp`、`SubscriptionPage.cpp`：输入、预览和展示；界面不写SQL。

后续移动App可以复用模型和应用层规则；当前存储与界面边界清楚，但没有账号、同步服务或移动通知。源码中不设置隐藏的远程入口。
