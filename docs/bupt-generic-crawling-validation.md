# 北邮教务处与通用办理指南采集整改

2026-10-05，继续以北京邮电大学官网首页 `https://www.bupt.edu.cn/` 测试陌生学校接入。本轮改动已进入共享 C++ 采集器，没有新增北邮学校包，也没有在生产规则中判断北邮域名或校名。大学识别、栏目发现、资源采集均不调用模型。

本轮共享整改随 0.1.2 更新预览版 `v0.1.2-r1` 发布；原 `v0.1.2` 及其附件保留。内部 `shared-fixes-v4/v5/v6` 是测试构建标识，不是软件版本号。五校实网结果冻结于 v4；本轮北邮使用 v5 生成学校配置，随后以 v6 复测资源。v5 至 v6 仅调整资源请求优先级、增加相应回归及原生验收参数，学校身份和栏目发现代码没有再次改变。

## 发现的实际问题

教务处首页除通知公告外，还有“学生服务”的导航。其中[选课和退课](https://jwc.bupt.edu.cn/xsfw1/xkhtk.htm)包含六项公开指南：选课安排、选课进程、重修选课、补修选课、退课、冲突选课；[考试和成绩](https://jwc.bupt.edu.cn/xsfw1/kshcj.htm)包含课程考核与成绩管理实施细则、考试纪律、补考、缺考。两份索引都没有列表发布日期，当前分页只有禁用按钮。

旧通知导航规则未识别这两个栏目。旧资源库虽保存过“选课和退课”入口，却没有检查其下的重修正文。“至少三条文章加一篇正文”的技术条件也不足以判断内容是当期通知：两个服务索引都符合这一条件，实际属于长期办理说明。

此外，真实官网菜单的一些 href 是 `<span ...>转换链接错误</span>`。旧接入记录包含这类编码路径的 HTTP400 和未访问项。这些地址应在解析时过滤，继续沿有效子菜单发现信息。

## 共享代码改动

1. [ResourceClassifier](../src/adapters/ResourceClassifier.cpp)统一识别学生服务、选课和退课、考试与成绩、学籍和办理指南等栏目语义，供通知发现和资源发现使用。
2. [SchoolOnboarding](../src/adapters/SchoolOnboarding.cpp)继续追踪这些导航，但不把服务指南索引当作通知来源启用。自动接入算法版本为 8，已有本机自动配置可以按版本重新发现。
3. [HtmlAdapter](../src/adapters/HtmlAdapter.cpp)在解析 href 前拒绝标签和控制字符，避免错误占位符占用请求预算；正常查询参数与真实子菜单保留。此次未增加专门的“无效链接跳过数”字段。
4. [ResourceDiscovery](../src/adapters/ResourceDiscovery.cpp)优先读取选课、考试与成绩入口，并完成已发现的重修、补考、缴费指南正文检查，再继续扩展一般管理栏目。优先级仍扣除同主机已请求数，其他主机可继续获得机会；请求上限和域名边界保持有效。
5. 资源文章的简介从真实正文提取。只有导航文字、空正文或受限提示的页面不会标为指南已核实。校内门户作为官方办事入口保存，登录受限状态明确显示。

这些改动针对栏目名称、网页结构和请求顺序，不依赖单校路径。回归样本保留真实 DOM 与官网出处，执行时同时使用测试大学主机验证通用性。

## 实网结果

独立接入探针只接受官网首页，自动生成学校身份与来源配置；没有手工追加部门网址或修改生成配置。资源探针随后加载同一自动配置并调用生产 ResourceDiscovery，使用隔离数据库，没有新增资源种子。

|项目|第一次资源整改 v5|请求顺序进一步整改 v6|
|---|---:|---:|
|资源请求数|32|32|
|保存的资源入口|50|57|
|已核实公开资源|11|13|
|已发现、待核实|35|40|
|需要登录|2|2|
|访问失败|2|2|
|选课和退课|已核实|已核实|
|考试和成绩|已发现|已核实|
|重修选课|已发现，未检查正文|正文已核实|
|补考|未收录|正文已核实|

v5 实网结果说明：增加关键词仍不足以保证读到关键正文。请求预算用尽前，一般规章与管理页面占用了机会。v6 在相同输入配置、相同 32 次上限下改善顺序，完成两项关键指南的真实正文检查；没有用样本测试替代实网结果。

学校识别与栏目发现两轮均完成 48 次有界请求、验证 15 个来源，报告的列表候选行数为 238。该数字包含来源之间的重叠，且本轮接入探针不写通知数据库，不能称为“238 条去重通知”。通知发现仍保留未扫描前沿；没有把指南索引启用为当期通知来源。

[重修选课](https://jwc.bupt.edu.cn/info/1254/2768.htm)的正文发布日期是 **2021-04-01**，明确让学生查看每学期信息门户教务处的具体流程。[补考](https://jwc.bupt.edu.cn/info/1273/2774.htm)发布日期是 **2021-04-02**，说明一般安排在下一学期开学后第 1–3 周。两页均通过独立公开 WebView 会话取得 HTTP200，并由最终资源采集器再次读取正文。它们提供办事依据，不证明 2026 年的确切报名、缴费或补考日期，也不自动创建日历期限。

门户认证链接来自官网浮层菜单，不是重修正文中的直接链接；软件保存其官网发现出处，标为需要登录，没有读取登录后的内容。部分校内地址解析为内网或请求超时，采集器保留明确失败状态。

- 最终 CTest **22/22 组通过**；自动接入日志 **35 passed**、HTML 日志 **50 passed**、资源发现最终日志 **36 passed**，均无失败。QtTest 的 passed 数包括初始化和收尾记录。
- 新增四份真实 DOM 裁剪样本，见[样本出处](../tests/fixtures/general-templates/provenance.json)。覆盖有效学生服务导航、坏 href、两份指南索引、历史重修正文与发布日期。
- [自动接入回归](../tests/OnboardingTests.cpp)、[HTML 回归](../tests/HtmlTemplateTests.cpp)、[资源回归](../tests/ResourceDiscoveryTests.cpp)验证指南分流、真实正文、空正文反例、关键指南优先及主机间机会。
- 原生验收从实网数据库生成临时副本，在桌面2打开生产“学校资源”页面，选择“重修选课”，验证 57 行、类别、访问状态、官方链接及详情。原数据库与资源保持不变，未发起额外网络请求、未打开系统浏览器。截图经过实际查看。
- 最终便携程序在只保留 Windows 路径、移除 QT 环境变量的条件下运行 `--version`，输出 `CampusPulse 0.1.2`、退出码 0；这项证明运行库能加载，原生界面结果另由上项验证。

本机证据位于 `D:\codex项目\CampusPulse官网对比审计\2026-10-04\`：`bupt-audit-agent/` 是独立只读审计，`bupt-live/` 保存公开页面与测试日志，`bupt-v5-fixed/proof.json` 是首页接入报告，`bupt-v6-resources/resources.json` 与 `native-proof.json` 是最终资源与界面结果。`bupt-build-manifest.json` 记录最终源码、样本与可执行文件哈希。网页缓存、数据库、设置和个人凭据不进入便携包。

## 仍有的范围限制

来源发现最多 48 次请求，资源发现最多 32 次请求，深度和官方 HTTPS 边界仍有限。最终资源 57 项中只有 13 项完成公开可用性核实，其余状态不能称为采集成功。教学通知分页按官网真实“下一页”链接跟进，启用来源最多更新三页；没有采集全校全部历史内容。

通知发现与资源发现是两个有界阶段，因此通知报告中未扫描的学生服务入口，可能已由资源阶段验证。两份报告要分别查看，不能合并成全量完成。账号门户、动态列表、更多学院及历史页面仍需继续扩展。

此前东北大学、大连理工大学、哈尔滨工业大学、山东大学、南京邮电大学的逐项对照见[五校报告](five-school-universal-validation.md)。五校实网数字属于冻结的 v4 构建；本轮最终共享代码通过五校 DOM 回归，但没有把五校重新实网采集一遍，也没有合并中间轮较大的数字。
