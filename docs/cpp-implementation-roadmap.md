# CampusPulse C++ 桌面版代码实施路线 v0.4

日期：2026-10-02。用户熟悉C，有学习目的，选择C++ + Qt；电脑软件先行，移动App后置。路线中的桌面骨架、本地存储、学校加载、HTML/CSS适配、异步实采、标题检索、多站点汇总、有限分页及年份/来源组合筛选已在原型0.1落地；其他步骤仍是计划。实际范围与证据入口见 [桌面原型说明](desktop-prototype.md)。

## 1. 第一版技术范围

- C++20 + CMake；具体编译器、Qt和依赖版本在工具链探测后锁定，构建不能依赖作者机器的隐含路径。
- 桌面功能原型建议 Qt Widgets + Model/View；视觉风格未定，QML 可在样稿验证后替换展示层，不预设移动端也使用 Widgets。
- Qt Network 执行异步请求；Qt SQL 的 QSQLITE 驱动连接 SQLite。数据放应用数据目录，不放源码或安装目录。
- 首个通用HTML适配器实际采用Lexbor 2.5.0的HTML解析与CSS查询，并用真实页面样本验证。原先libxml2/XPath候选未使用；配置明确query_language=css。动态站点与其他解析路线后续扩展，不散布临时正则修补。
- 原有 Python 脚本保留为开发期学校配置检查工具；桌面运行时不依赖 Python。用户导入配置的必要语义检查需在 C++ 中实现并对齐契约。
- AI 摘要、云账号、移动同步、动态插件市场都后置。首版保留附件元数据和官方链接，PDF/OCR/表格全文提取按来源需求增加独立解析器。

官方能力依据：[Qt CMake](https://doc.qt.io/qt-6/cmake-get-started.html)、[异步网络与线程归属](https://doc.qt.io/qt-6/qnetworkaccessmanager.html)、[Model/View](https://doc.qt.io/qt-6/model-view-programming.html)、[Qt SQL](https://doc.qt.io/qt-6/qtsql-index.html)、[libxml2 HTML解析边界](https://gnome.pages.gitlab.gnome.org/libxml2/html/HTMLparser_8h.html)。

## 2. 依赖边界及预计目录

```text
CampusPulse/
├── CMakeLists.txt / CMakePresets.json
├── src/
│   ├── domain/         通知、日期、人群、事项、步骤、个人状态
│   ├── application/    查询、导入、更新、跟踪与完成操作
│   ├── adapters/       网络、HTML、学校包与将来的其他来源
│   ├── storage/        SQLite仓库与数据库迁移
│   └── desktop/        窗口、Controller、ViewModel、列表模型
├── configs/ / schemas/ / templates/
├── migrations/
├── tests/fixtures/     脱敏网页样本、预期结果、日期和更新案例
├── tools/             配置检查及计划中的包验证CLI
└── docs/
```

domain/application/adapters/storage/desktop和CMake已创建；其余计划资产按需要增加。源码目标依赖：domain不依赖Qt、SQL、网络；application依赖domain和能力接口；adapters/storage提供实现；desktop组装并调用。Qt对象和类型在边界转换，不泄漏为公共领域模型。

先产生有用途的具体类，只有需要替换采集/存储实现时引入接口。禁止界面里直接拼SQL、抓网页、解析日期；禁止适配器里判断个人完成状态；不为每个类建立空接口和工厂。配置与适配器以稳定ID引用，核心无大学名称分支。

## 3. 逐步实施

### 步骤0：确认工具链并锁定构建方法

检查已安装编译器、CMake、Qt kit、目标平台、SQLite插件与依赖获取方式；PATH里找不到不代表未安装。选择一套ABI兼容的编译器和Qt，记录配置命令。工具不存在时再安装所需组件，不同时堆多套编译链。

产出：依赖版本记录、CMake配置方案、构建README。验收：最小Qt程序能编译和启动；此时不声称采集或提醒完成。

### 步骤1：建立可编译的最小骨架

创建 CMake目标 domain、application、adapters、storage、desktop，只给目标链接需要的模块；main.cpp 组装依赖，MainWindow 先显示少量假数据与来源标签。

产出：可启动窗口和初步构建脚本。验收：干净构建成功，窗口响应正常，依赖方向可以从CMake检查。主要学习：类、头文件/实现分离、命名空间、RAII、Qt信号槽。

### 步骤2：写领域类型和离线通知查询

先实现 School、Source、Notice、NoticeRevision、DateValue、Evidence；DateValue 区分纯日期、精确时间、未知，不用一个空时间戳混装。数据使用值对象、标准容器和明确所有权。

实现 QueryNotices 操作及内存仓库，用标准化样本数据驱动 NoticeListModel；此时可按主题/学校筛选并查看原文URL。办事复杂模型随步骤7加入，不一次写完所有计划表。

验收：混合日期、中文标题、空日期正确显示；筛选不依赖某学校名称。主要学习：vector/string、optional、枚举、const、接口与值语义。

### 步骤3：加入SQLite持久化与版本

实现 DatabaseMigrator、SqliteNoticeRepository；首批迁移建 schools/sources/notices/notice_revisions/evidence/fetch_runs，保持现有逻辑模型的稳定身份和版本关系。参数化SQL与事务处理一轮更新，实际SQL独立于领域规则。

保存、关闭软件、重启读取；重复导入不生成重复通知；正文变化新增revision；访问量变化不生成语义更新。随后随订阅、任务、提醒功能增加迁移，不把规划中的所有实体一次落成空表。

验收：重复导入、事务失败回滚、更新历史、重启和迁移均正确。数据库连接由所属线程创建和使用，后台处理不跨线程复用同一Qt SQL连接。

### 步骤4：大学配置加载与离线HTML适配器

实现 SchoolPackageLoader、HtmlDocument、HtmlListDetailAdapter。先读取本地列表/详情样本，使用配置提取文章身份、标题、URL、发布日期、正文、附件链接和下一页。适配器参数定义 parser/query_language，首个XPath实现不宣称支持CSS。

原文编码、相对链接解析和身份参数保存要有样本；无正文、分页循环、必需字段缺失返回结构化错误。HTML库用RAII封装，错误包含 source_id、阶段和诊断，不能吞掉异常返回空通知。

对比至少两种不同布局的样本和配置，证明核心与界面无需修改；人工构造样本可用于结构回归，不能作为真实新校接入成功证据。

验收：预期字段、下一页及失败样本可复现；未知解析配置拒绝启用。同步实现C++配置字段/引用校验，对照当前Python开发工具。

### 步骤5：接入异步网络和更新调度

实现 QtHttpClient、FetchCoordinator 与手动刷新操作：列表请求 → 解析条目 → 详情请求 → 标准结果 → 版本提交 → 通知界面。首个真实来源可用东电，也可替换任意已确认来源。

增加超时、取消、响应状态、允许域与重定向校验、同域限流、条件请求；游标只在对应处理成功后推进。Qt网络对象始终在所属事件循环线程使用，不能用同步等待阻塞UI。解析与批量存储必要时放后台线程，UI仅处理进度和结果。

定时更新在软件运行时执行，重启补查变化；先不实现系统常驻服务。首次历史回填默认不弹出大量提醒。

验收：刷新中窗口可操作，取消有效；断网/超时可见；成功内容不重复入库，失败来源不显示成“没有通知”。

### 步骤6：关键词检索、主题与订阅

实现 KeywordMatcher、CategoryRules、SubscriptionFilter、NoticeSearch。明确包含词 any/all 与排除词含义，支持学校、来源、主题和受众过滤；组间OR、组内AND。

先用确定性规则和可解释命中原因，搜索从数据量适当的实现起步；中文检索先验证包含搜索与索引选型，不假设默认全文分词就适合中文。原文日期、教师通知、历史政策不能仅因关键词命中进入个人期限提醒。

增加 subscriptions 与配置版本迁移；在界面预览命中通知再保存。多校订阅必须保留每组学校与条件关系。

验收：规则优先级、中文搜索、多校组合、未知受众与重复命中得到预期结果。社区可通过配置扩展来源分类提示，不能重写核心订阅。

### 步骤7：时间证据、校园事项与个人待办

实现 DateExtractor、CaseAssembler、ActionStep、UserTaskService。日期提取先处理明确年月日及截止上下文，相对/跨年/冲突时间进入待核实；建立统一审核状态，自动规则批准与人工修正都有记录。

时间/步骤保留原文依据；报名、缴费、材料提交分别建节点。多通知组成Case时校验学校、学期/批次与人群；不靠标题关键词自动合并。

用户主动加入计划，状态分未开始/进行中/用户自报完成/不再跟踪；已读独立。重采集和时间更正不清空个人完成状态。增加对应数据库迁移和操作版本。

验收：重修报名完成后缴费仍未完成；奖学金公示不变成申请截止；补考可以没有报名/缴费步骤；无日期不编造期限；后续更正保留原事项身份和操作历史。

### 步骤8：桌面提醒与ICS导出

实现 ReminderPlanner、LocalReminderStore、QtDesktopNotifier、IcsExporter。软件运行时扫描到期任务，完成/暂缓后撤销未触发计划；触发后持久记录，重启不密集重发过期提醒，来源变更重新计算。

桌面通知还依赖系统权限和实际通知机制，必须在Windows实际查看；不能仅因调用通知接口认定提醒已显示。退出或关机时不保证催办，应用应说明当前运行能力。

先提供ICS文件导出与明确的日期精度/稳定UID/更新序列。单次导入的日历不是持续订阅：需要后续稳定可访问服务才能提供手机可持续刷新的私人feed，不能把本地文件当作线上订阅完成。

验收：真实桌面提醒、完成后停止、延期后重排、ICS格式及日期精度正确；日历导入结果另行实测。持续手机提醒后置。

### 步骤9：社区包验证与通用性回归

从第一版保留贡献模板和离线样本；此时将可运行适配器暴露给包验证CLI，补齐fixture manifest/预期输出runner、包版本、兼容性与变更预览。配置导入不执行第三方脚本。

选真实第二/第三学校、不同站点结构，按贡献指南新增包；错误配置拒绝、失效来源可定位、升级可以回退配置版本而不破坏用户任务。增加实际CI，权限与联网范围按平台框架约束。

验收：有另一个贡献者能依据指南新增来源，核心与桌面无学校分支；不能仅以复制两个配置宣称支持多校。

### 步骤10：打包发布准备与后续移动接口

打包Windows应用及必要Qt插件/依赖，使用干净环境验收启动、路径、日志、升级迁移与卸载行为，附带依赖许可。检查安装后不要求源码目录、Python或开发环境。

当前预留稳定ID、序列化DTO、版本与变更记录；明确应用操作入口，例如QueryNotices、JoinCase、CompleteTask。移动/服务端设计开始后再落实认证、同步游标、冲突和API，不提前开一个无管理的网络监听端口。

发布和安装对外行为按当时用户授权执行。本路线不承诺未来某日期交付，也不把计划测试写成已经通过。

## 4. 小步交付与学习节奏

每一步提交可编译结果，说明新增类及职责、运行方法、验证证据和剩余限制。先用到再介绍继承、多态、智能指针、线程等知识；不为展示技巧引入复杂模板、协程或微服务。

第一个有用的里程碑是：启动软件、加载离线样本、筛选通知、保存并重启恢复。第二个是：加入真实官网更新和可解释检索。第三个是：个人待办与实际桌面提醒。社区包能力与这三个里程碑一起演进，移动端在后续独立里程碑接入。

开发检查针对行为：解析结果、版本幂等、事务、日期证据、订阅、任务完成与提醒。普通文案或布局变更不追加只复述实现的测试；静态检查不代替实际窗口和通知验证。
